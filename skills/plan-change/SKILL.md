# Plan a change

Inspect the project instructions, relevant source material, tests, and current workspace state before proposing the plan. Separate confirmed facts from assumptions.

Produce a plan that states:

- objective, acceptance criteria, and explicit non-goals;
- affected components and dependency boundaries;
- ordered implementation steps with observable outcomes;
- verification for each material risk;
- decisions that require human input.

Do not modify implementation files while planning unless the user explicitly asks for both planning and execution. Ask only when a missing decision would materially change the result; otherwise state a bounded assumption.
